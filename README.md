# llm_wiki — context hub for AI-assisted projects

One place to see every project's state. Per-project context lives **in each project's
own repo** (so it versions atomically with the code and `git show` recovers any old
version); this hub holds the universal rules and aggregates the states.

Setup: [`docs/new-machine.md`](docs/new-machine.md) · commands: [`CHEATSHEET.md`](CHEATSHEET.md) · day-to-day: [`USAGE.md`](USAGE.md) · why it's built this way: [`docs/research-report.md`](docs/research-report.md) · what got added in v2 and why: [`docs/v2-triage.md`](docs/v2-triage.md).

## Install

```bash
# one command does all of it (CLI, commands, subagent, hooks, verification):
~/projects/llm_wiki/bin/llmw-install
```

<details><summary>or manually</summary>

```bash
# 1. make the CLI reachable
ln -s ~/projects/llm_wiki/bin/llmw /usr/local/bin/llmw

# 2. global slash commands + subagent (apply to ALL projects)
ln -s ~/projects/llm_wiki/commands/*.md ~/.claude/commands/
ln -s ~/projects/llm_wiki/agents/code-explorer.md ~/.claude/agents/

# 3. hooks — merge hooks/settings.json into ~/.claude/settings.json,
#    replacing HUB_PATH with /Users/rajeevkumarachra/projects/llm_wiki

# 4. version it
cd ~/projects/llm_wiki && git add -A && git commit -m "chore: init context hub"
```

</details>

## Per project — once

```bash
cd ~/projects/some-project
llmw init          # creates .context/, CLAUDE.md, standards symlink, post-commit hook
claude             # then run /onboard to fill the templates from the actual code
git add .context CLAUDE.md && git commit -m "chore: add project context"
```

## Daily loop

| Moment | What happens |
|---|---|
| open Claude Code | SessionStart hook injects branch, dirty files, recent commits, `state.md`, last 5 log lines, and the standing rules from `lessons.md` — **~450 tokens, no prompting** |
| lost the thread | `/catchup` |
| made a real decision | `/adr <what you decided>` |
| before quitting | `/wrap` — rewrites `state.md`, appends to `log.md` |
| any commit | git hook appends a log line automatically |
| across projects | `llmw sync` → regenerates `index.md` |
| feels stale | `llmw lint` |
| before a risky change | `/preflight` — constraints + blast radius + rollback |
| before committing | `/verify` |
| AI broke something | `/incident` — turns it into a permanent rule |

## Layout

```
standards/       universal rules — ONE copy, symlinked into every project
  00-core.md       session protocol, ground rules, change protocol, token discipline
  10-code.md       style, structure, errors, tests, dependencies
  20-safety.md     never-touch list, destructive commands, security defaults
templates/       what `llmw init` installs
projects/        one hub page per project
commands/        /wrap /catchup /adr /onboard /preflight /verify /incident
patterns/        cross-project reusable patterns (2+ projects only)
agents/          code-explorer subagent (isolated context for exploration)
bin/llmw         the CLI
hooks/           settings.json snippet
index.md         generated by `llmw sync`
log.md           global chronology
```

## The one rule that keeps this alive

> **Write down only what cannot be cheaply re-derived from the code.**

Decisions, business rules, constraints, glossary, incidents, where-we-stopped → write
them down. File lists, dependency graphs, feature file-lists, API signatures, TODOs →
derive them live:

```
llmw impact <path>    what breaks if I change this (static refs + historical coupling)
llmw feature <name>   which files implement it, right now
llmw todos            TODO/FIXME/HACK debt, by file
llmw timeline         how the architecture evolved
```

A stale doc is worse than no doc, because the agent trusts it.
